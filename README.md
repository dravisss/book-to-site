# Book-to-Site

Turn a PDF book into a self-contained interactive website — full text, real
figures, translated by cheap LLM workers. No summaries, no external hosting:
the output is a **single HTML file** that works offline over `file://`.

Built and validated on academic books (e.g. *Organization Theory* by Hatch,
*Sociological Paradigms* by Burrell & Morgan) and now published as a
reusable, provider-agnostic pipeline.

> **Intended use — public-domain books only.** This project is designed for
> books in the public domain (e.g. from Project Gutenberg or Wikisource) and
> for material you own or are explicitly licensed to reproduce, translate,
> and distribute. **It does not encourage piracy.** If you do not hold the
> rights to a book, translating and publishing its full text may violate
> copyright — always check the source's license before running the pipeline.
> Good sources: [Project Gutenberg](https://www.gutenberg.org), Wikisource,
> open-access works with permissive licenses, and your own writing.

## Features

- 📖 Full-fidelity translation (master-slave LLM workers, cheap model per worker)
- 🖼️ Real figure extraction (gap analysis — no page scans)
- 🔍 Sidebar navigation, footnote tooltips, full-text search
- 🎨 Configurable design system (default: Forest Floor — light/dark/sepia)
- 📦 Single-file SPA, works offline, no server required

## How it works

```
PDF → extract.py (pymupdf) → chapters/ + images/
              ↓ (optional) extract_figures.py → real figures
       LLM workers → translated chapters *_PT.md
              ↓
       build_site.py → single-file SPA
```

## Requirements

- Python 3.9+
- `pip install pymupdf Pillow`
- **Recommended for books with figures or scanned PDFs**: the `docling` CLI
  (produces markdown with images embedded as base64 — the pymupdf gap
  analysis misses figures embedded in page scans)
- For the translation phase: the [Hermes](https://hermes-agent.nousresearch.com)
  CLI with any configured provider/model (the worker contract is
  provider-agnostic — see SKILL.md). The extraction + build phases run
  without Hermes.

## Quick start

```bash
# 1. Extract text and figures
#    Path A (recommended when figures matter): Docling
#      docling book.pdf --to md --output . --image-export-mode embedded
#    Path B (lightweight, no Docling):
python3 scripts/extract.py book.pdf --out-dir output
python3 scripts/extract_figures.py book.pdf --out-dir output/imagens

# 2. Translate the chapters (master-slave workers) → output/capitulos/*_PT.md
#    See SKILL.md → Worker Contract for the canonical prompt and command.

# 3. Build the site
python3 scripts/build_site.py --chapters-dir output/capitulos \
  --images-dir output/imagens --output site/index.html \
  --title "My Book" --authors "Author Name" --lang en

# 4. Open
open site/index.html
```

## The translation phase (master-slave)

The pipeline is designed around a master agent orchestrating cheap workers:

```bash
export WORKER_MODEL=deepseek-v4-flash   # any cheap fast model
export WORKER_PROVIDER=opencode-go      # your provider
hermes chat -m "$WORKER_MODEL" --provider "$WORKER_PROVIDER" \
  --quiet --max-turns 4 --cli -q "$(cat prompt.txt)"
```

Validated stack: flash-tier models (e.g. `deepseek-v4-flash`) are good enough
for both orchestration *and* translation — no need for an expensive master.

## Customizing the design

All CSS variables live in `:root` inside `templates/site.html`. Recolor the
site by editing the variables, or replace the whole template file — the build
script only needs the placeholders (`__BOOK_TITLE__`, `__BOOK_AUTHORS__`,
`__BOOK_YEAR__`, `__LANG__`, `__BOOK_DATA__`).

## Limitations

- The translation phase requires the Hermes CLI (extraction + build are
  standalone). The worker contract is documented so other agents can adapt it.
- Scanned PDFs need Docling or accept pymupdf text + LLM re-writing of OCR.
- Very large books (500+ pages) need manual chapter mapping from the TOC —
  auto-splitting by headings produces broken structure.
